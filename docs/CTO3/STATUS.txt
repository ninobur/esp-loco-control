## Dashboard saga (Flask ngr_app.py)
- v1.10.x progressively added "smart" confirmation-gating that DEGRADED manual
  control from "delightful" to inert — the opposite of the bicameral ruling.
- Root causes found: throttle published on release not drag; direction waited on
  an echo QUORUM's vocabulary didn't send ("Waiting for Otto" = the wrong-loco
  listener, later found to be a WORDING bug not a binding bug); server mqtt_lock
  made manual commands wait behind telemetry parsing while E-STOP skipped it;
  stale telemetry disabled the throttle.
- DECISION: live Pi ROLLED BACK to v1.9.5 (pre-degradation, works). Repo raced
  ahead to v1.10.9. Live Pi != repo.
- Governing principle going forward: manual = dumb/direct/unblockable (E-stop
  model); informational features (telemetry, polarity tile) belong on a separate
  diagnostic view, NEVER wired into control enabled-state. The polarity
  agreement tile is a keeper — it diagnosed a dead sensor and a flipped sensor
  live.
- Real bugs still open on the repo dashboards: E-stop doesn't zero throttle,
  brake does nothing (no firmware channel), INA219 blank (no firmware channel).

## Latency — root-caused, not signal
- 5-hour RSSI survey (survey car built this session, IR-speed + RSSI on one
  ESP32): NO dropout, -38 to -65 dBm loop-wide. Wi-Fi shadows RULED OUT.
- Latency was the dashboard's "smart" logic in the command path. E-stop was
  responsive because it bypassed the logic; throttle/direction weren't. Fixed in
  the command-path rewrite (oninput, lock removed, ~0.5ms to broker measured).

## Survey / IR car

## CTO3 (multi-train) — carried from history into the repo
- Operator's key architectural restatement: ONE bicameral control sketch; the
  ONLY chamber crossings are E-STOP, enlistment (manual->auto, loco's own act),
  release (dispatcher->manual), and dispatcher STOP (enrolled locos only).
  QUORUM 1.6 already implements this — audited and confirmed.
- Physical envelope: 18" forward, 48" behind the Hall sensor (config, not
  constant). Supersedes old 2ft/5ft bubbles.
- Travel-direction rule (operator insight, explains "QUORUM doesn't do
  reverse"): travel_direction = session_direction XOR motor_reverse. Needs
  SOURCE VERIFICATION before any firmware change.
- Speed: SPEED_HOLD not THROTTLE_HOLD. PWM is actuator, measured pKPH is
  controlled variable. Source hierarchy HALL_VALID->HALL_AGING->PWM_ESTIMATE->
  MOTION_UNCONFIRMED. Hard "U-Haul in the median" law: never escalate PWM on a
  zero-speed reading. Empirical ceiling ~70/75/80 pKPH. Speed floor ~2.5s/marker.
- Learned segment x direction x PWM -> pKPH table (Pi = brain/archive, ESP32 =
  ~2KB distilled copy; Pi never in the control loop). Voltage a required
  dimension (INA219). Calibration grid PWM 25/30/35/40/50/70 both directions.
- Documents committed: docs/CTO3/CTO3_INTENT_BASELINE.md, CTO3_SPEC.md (draft 1,
  14 sections), resources/. IR does NOT block CTO3 (decision 0003) — build the
  IR-independent core now; only the calibration campaign waits for IR evidence.
- CTO3 is Lowline-only; blocks are gone; station stops are mapped locations, not
  QUORUM positions. Collision awareness is a property of every loco, not a pair.
  CTO2 failure lesson: unknown/stale traffic is NEVER converted to clearance.
