# NAVI implementation reconciliation and discrepancy inventory

**Audited snapshot:** `NAVI_POWER_OF_NORMAL_MANUAL_ONLY_export_20261024.zip`, exported 2026-10-25 02:55, branch `dev/navi-power-of-normal-manual-20261024`, base `ae90cceed9b03af32b49650f1212aa909980cdf2`. The export contains six modified tracked files and two untracked headers. It is not committed. It is a manual-only experimental sketch, not Balloon/production integration.

**Audit basis:** source code and tests in that export; `NAVI_TWENTY_ORIGINAL_AGREEMENTS_20261024.md`; `NAVI_POWER_OF_NORMAL_RECONCILED_SPEC_20261024.md`; `NAVI_POWER_OF_NORMAL_INTEGRATED_IMPLEMENTATION_PROPOSAL_20261024.md`; the recovered engineering transcript; NGR sensor-data and design-philosophy records; and David's later explicit decisions on 2026-10-24. No firmware was changed.

## Governing cycle

1. The declared map position and direction establish exactly one expected next marker.
2. Per-interval opening-to-opening movement history predicts the expected marker's geographic/time neighborhood.
3. Continuous Hall observation finds a 70-count, two-consecutive-sample opening.
4. NAVI observes the complete magnetic passage and evaluates the one expected target.
5. Geographic timing, opening polarity, minimum physically plausible width, and observed completion are all required identifiers. Timing cannot create a magnetic confirmation or override wrong polarity.
6. A qualifying passage advances exactly one marker. A nonqualifying passage retains the same target and observation continues.

Repeated 70×2 crossings within a single physical passage belong to that encounter's ensemble. The first genuine opening anchors its timing; re-crossings cannot create an extra marker. The later decision removes the navigation late-arrival stop response. It does not remove movement/timing from recognition.

## Summary finding

The export corrects several earlier architectural defects: no global candidate lockout, no timeout/abandonment state, baseline collection is no longer delayed until the short confirmation, and a nonqualifying encounter retains the expected target. Those are real improvements.

It does **not** yet implement timing as an active recognition identifier. `NaviTimingPredictor::agrees()` returns `true` for every input, and the included replay does not pass timing data into encounters at all. The 177-marker field run consequently cannot demonstrate timing-informed qualification.

The exported sketch also contains stale stop-and-hold references that make the full sketch fail to compile as exported. The host unit tests compile only headers and therefore did not detect this.

## Findings that need field/raw evidence, not a code patch

- The first MM52–58 failure and the later compensated CW lap support a speed/track-dynamics hypothesis but do not establish its cause. The log alone cannot identify sensor geometry, physical marker identity after divergence, or a true stall.
- The repeated 70×2 crossings are not a defect merely because they are multiple. They require native-record examination as one ensemble.
- The current `RTB_RUN_BLOCKS`, `RTB_MARGIN_ADC`, minimum width, baseline entry band, baseline live recompute cadence, movement eligibility, and timing tolerance each need evidence and explicit status. A passing count must not convert any of them into approved architecture.
- CCW remains untested from the supplied field evidence; it must be declared and driven in CCW before conclusions about CCW recognition are drawn.
