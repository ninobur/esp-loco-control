## 1. Proposal boundary and source basis

This is a clean-sheet design proposal based on the conference record, the independent r5.1 audit, and direct inspection of the audited sketch and its included local headers at `5b7a518b`. Previous implementation attempts and proposals do not define this design. The r5.1 code is used only to identify functioning operational behavior, interfaces, and incompatible navigation mechanisms.

The proposal describes behavior and candidate component boundaries. It does not select unresolved observation, baseline, width, arrival-boundary, or pace-limit policies. Recommendations below are recommendations for an operator decision, not adopted design. Firmware work, test implementation, specification changes, and field changes require separate explicit authorization.

## 2. Architecture interpretation

NAVI follows one normal geographic sequence. It starts from an operator-confirmed position and travel direction. The route map supplies the unique next marker, its mapped polarity, and the interval spacing. Movement history and the approved pace model estimate where and when that one target should arrive. NAVI does not compare a signal against a set of possible route identities, search ahead, skip markers, or recover a geographic position from a surprise observation.

Hall acquisition runs continuously. Each observation remains available to the navigation observer regardless of motor output, AUTO status, station dwell, an unresolved encounter, or a protective hold. Acquisition and geographic judgment are separate responsibilities: recording a Hall value does not itself change position, and a navigation decision cannot pause the observer.

A 70-count, two-consecutive-sample onset sentinel marks a candidate. NAVI preserves the evidence and waits for the Hall trace itself to return to baseline. Only after observed completion does it assess the complete encounter using the approved evidence: opening polarity and minimum physically plausible width, with completion established by the observed return. The minimum width is a lower bound for candidacy, not a target waveform shape. General shape metrics can be retained for diagnosis and later evidence review, but cannot reject an otherwise qualifying event.

If the completed encounter qualifies and its polarity matches the one expected target, that target is confirmed and the geographic sequence advances by exactly one mapped position. A candidate that fails qualification, or a completed encounter that does not qualify, leaves the expected target pending. NAVI keeps observing for that same target. Such an observation does not trigger a contradiction state, alternate identity search, or immediate geographic stop.

For each mapped interval, a separately validated pace-normalized latest permissible arrival boundary defines how long normal waiting may continue. If the expected target has not been confirmed by that boundary, NAVI requests a protective stop-and-hold. The last confirmed position stays authoritative; Hall acquisition continues during the hold. The boundary-setting method, per-interval data sufficiency, pace adjustment and its limit are open decisions; this proposal assigns no numerical value.

The railroad is a physical known route, not a general-purpose signal classification problem. The map says which one magnet comes next. The sensor establishes whether a qualifying magnetic passage occurred. The arrival boundary determines when waiting for normal progression has lasted long enough to protect the locomotive. Each part has one authority.

## 3. Observation and qualification process

### 3.1 Observation contract

The observer receives timestamped Hall samples or an explicitly approved sampling representation in chronological order. The observer runs continuously and publishes evidence independently of navigation state and motor state. Recording raw samples and deriving an observation stream are separate concerns: any buffering, transport, or queue policy must not silently discard input used by recognition. If real-time resource limits make unconditional delivery technically infeasible, the constraint and evidence must be brought back as a design issue; a suppression rule must not be invented as an implementation convenience.

The conference specifies a 70x2 onset sentinel and retrospective evaluation at observed return to baseline. It does not specify the ADC sampling rate for the new implementation, exact sample representation, baseline/reference policy, how to define return to baseline under noise or slow drift, behavior for a missing/invalid sample, the memory bound for an open encounter, or how to retain evidence when multiple candidates are observed before a prior one completes. These affect what NAVI observes and qualifies and therefore require decisions before implementation.

An encounter record should carry its evidence and provenance (sample times, observed values, opening polarity, completion point, width, and any diagnostic metrics) so the geographic judge can make a decision only after completion. This record is a proposed interface, not a decision about storage format or an additional waveform filter.

### 3.2 Successive encounters

The expected-target model implies successive qualifying encounters are handled in sequence: after target k is confirmed, the mapped next target becomes k+1. But the conference does not detail how an encounter beginning before the preceding encounter has returned to baseline is represented, whether the physical spacing guarantees non-overlap at all allowed speeds, or what the observer should do if two candidate onsets occur during one incomplete encounter. No overlap-merging, candidate replacement, timeout-based completion, or lockout is assumed here. Resolve this with route spacing and recorded traces before coding.

### 3.3 Qualification limits

Qualification includes the approved opening polarity and a minimum physically plausible width, plus observed completion. The source of polarity (opening samples, peak, or another approved polarity measure), width measurement convention, and numerical minimum remain open. The conference explicitly makes shape diagnostic only. A Gaussian fit, smoothness score, lobe count, residual threshold, or other generalized morphology score cannot be an admission or rejection gate.

## 4. Geographic judgment

The route map and last confirmed position establish a single expected target. Direction selects the next mapped position; the map supplies its polarity and interval spacing. Recent movement history contributes the predicted location/arrival estimate and, once approved, the current-pace adjustment for the arrival boundary. Spacing and polarity are route facts used to describe and qualify the expected event; they do not authorize alternatives to the expected position.

The geographic state should minimally represent: whether a confirmed starting declaration exists; last confirmed marker; direction; exactly one expected marker; movement history needed by the approved prediction/boundary method; and whether NAVI is waiting or has issued the late-arrival hold request. A qualifying, expected-polarity encounter confirms the expected marker and advances once. A candidate not meeting approved qualification leaves that state unchanged. This avoids the r5.1 `Contradiction` behavior, where a wrong-polarity accepted ensemble immediately enters a stop-producing state.

Operator declaration and direction/session transitions need an explicit contract. The audit shows r5.1 uses operator declaration and suspends when direction/session changes. This proposal does not decide which commands may create or replace a confirmed geographic starting point, what happens to movement history on redeclaration, or whether a new declaration can occur while a protective hold is active.

## 5. Protective behavior and operational authority

The late-arrival boundary is part of ordinary progression: each mapped interval gets an empirically validated latest permissible arrival adjusted by an approved current-pace method. Until that boundary, absence of confirmation means continue waiting and observing. At the boundary, NAVI requests stop-and-hold, records the expected target and last confirmed position, and keeps observing. NAVI does not claim to know why the target was late.

NAVI’s late-arrival hold is one motor request authority. Existing authorities remain distinct:

- Emergency stop and battery protection can override motor output independently of NAVI.
- Manual STOP, throttle, brake, and direction remain operator/command functions.
- AUTO cruise, ramps, station approach, station dwell and departure remain operational behavior.
- ESP-NOW peer coordination and bubble spacing remain operational behavior.
- Route/grade configuration remains an operational throttle input based on confirmed geography.

These functions may request or constrain motor output, but they do not write NAVI’s confirmed position. Station/bubble code must consume a read-only snapshot of confirmed geography. An operational stop or dwell must not disable Hall observation or reset the geographic target. A protective hold must not cancel observation, and a later Hall observation during hold must not silently release the hold or advance a target without the specified completed qualifying event and an authorized motor-release rule. That release rule is open and requires operator decision.

The conference says NAVI requests protective stop-and-hold when the boundary expires. It does not settle how this request arbitrates with AUTO ramps, manual mode, existing station holds, E-stop, battery protection, STOP/GO commands, or a subsequent valid arrival during hold. Existing higher-priority safety authorities must retain their independently established behavior, but the NAVI request’s latching and release semantics must be agreed before implementation.

## 6. Proposed software boundaries

Boundaries below are justified only by the conference’s responsibilities; they are not a mandate to add a large framework.

| Proposed responsibility | Narrow behavior/interface | Conference basis |
|---|---|---|
| Hall acquisition and continuous observer | Accept ordered Hall evidence continuously; expose samples to encounter evaluation irrespective of motor/navigation state. | Observe: unconditional continuous observation. |
| Encounter evaluator | Apply the 70x2 onset sentinel, retain a candidate, establish completion from observed return to baseline, and report full evidence for qualification. No shape veto. | Qualify: sentinel, retrospective complete encounter, shape diagnostic only. |
| Qualification rule | Apply approved polarity and minimum-width evidence only after observed completion; report qualified/not qualified with evidence. | Qualify: approved evidence and minimum physically plausible width. |
| Geographic state/judge | Hold exactly one expected target; confirm and advance one on qualifying expected evidence; otherwise preserve target and continue waiting. | Expect; Confirm or continue waiting; no search/recovery. |
| Interval arrival evaluator | Calculate the approved pace-normalized latest permissible arrival for the one interval and signal boundary expiration. | Protect: empirical interval-specific boundary and pace normalization. |
| Protective request adapter | Turn boundary expiration into a stop-and-hold request while leaving observer and confirmed geographic state active. | Protect: stop movement, retain position, continue Hall observation. |
| Operational integration | Consume read-only position/status; preserve current operational authorities and route/station/bubble behavior. | Geographic authority separated from locomotive operational authority. |

The first six responsibilities may ultimately fit into fewer source files. The component boundaries describe authority, not a demand for one class per row. Do not introduce a hypothesis manager, geographic recovery engine, waveform classifier, fault diagnoser, observation gate, baseline manager, or generalized stop-reason subsystem without evidence and explicit review.

## 9. Verification plan (proposal only)

Verification should demonstrate the complete agreed cycle against recorded evidence before hardware operation. The plan below defines evidence to collect; it does not authorize tests, firmware, or field runs now.

1. **Input provenance and replay preparation:** identify raw recordings, timestamps, locomotive, direction, speed/PWM conditions, route interval, and quality gaps. Preserve the distinction between acquisition samples and any derived block stream. Resolve historical onset-vs-RTB timestamp conventions against source data.
2. **Recorded Hall-data replay:** replay complete traces through the proposed observer, encounter completion, qualification, geographic judgment, and interval boundary together. Include normal passes, secondary lobes/rebounds, drift, stops/dwells, missing samples, and the documented historical events MM110, MM146, MM169, and MM113 where raw evidence exists. Do not claim physical causes when raw evidence is absent.
3. **Successive mapped magnets:** for both directions and all recorded intervals, demonstrate exactly one expected target, expected polarity/spacing use, one-position advance on qualification, and no skip/search/recovery. Report false accepts, false nonqualifications, late boundaries, and intervals lacking evidence.
4. **Continuous observation:** verify observer input count and time sequence remain continuous across motor-off, motor-on, station dwell, command STOP, NAVI hold, and unresolved candidates. Exercise acquisition-buffer capacity and prove no silent observation suppression. Confirm that a confirmed stop does not shut off the observer.
5. **Nonqualifying encounters:** include wrong polarity, width below the approved minimum, incomplete/no observed return, secondary lobe, and diagnostic-shape anomalies. Demonstrate that each leaves the same target pending unless it meets the approved qualification rule, and that only the interval’s approved late boundary produces NAVI hold.
6. **Protective stopping and STOP/GO:** replay target absence through the approved boundary, then verify hold request timing, retention of last confirmed position, continuing Hall evidence, operator STOP/GO semantics, and no automatic release/restart outside the approved rule. Exercise competing E-stop, low-voltage, station, bubble and manual requests to show safety/operational precedence and no geography mutation.
7. **Integration with locomotive functions:** compare r5.1 operational baselines for manual throttle/ramping, direction, AUTO start/stop, station approach/dwell/departure, ESP-NOW coordination/bubble, MQTT/operator commands, battery monitoring, E-stop, route/grade configuration. NAVI may supply confirmed geography and a protective hold request; operational code must not write geography.
8. **Compilation and hardware:** after explicit implementation authorization and closure of blocking decisions, compile the exact target configurations, then conduct bench/sensor testing and controlled hardware trials. Record binaries, source revision, configuration, run conditions, raw Hall evidence, motor requests, and position decisions. Expand speed/direction/loco/consist coverage before accepting numerical width or arrival-boundary values.

Acceptance must be end-to-end: the system must observe continuously, qualify only from approved complete evidence, advance only the expected target once, wait through nonqualifying observations, and request hold only after the approved late-arrival boundary. A component test alone cannot establish fidelity.
